# SACUTE UI/UX audit and implementation

Reviewed on 29 October 2026. Changes are local and uncommitted. Nothing was deployed or pushed.

## A. Findings and priorities

The application is a Vietnamese student-support information site. Its six public routes help students find announcements, scholarships and events, contact SACUTE through its supplied channels, and explore five recruitment teams. The existing React Router 7 / React 19 frontend, NestJS API, shared content model, route structure, navigation order, official logo and recruitment copy are retained.

The checkout was clean when work began. No applicable `AGENTS.md` was found in the checkout, its parent directories, or application/test subdirectories. Repository source and conventions were inspected before editing. The local production application was launched on `http://127.0.0.1:4173`.

All six deployed routes at [sacute.vercel.app](https://sacute.vercel.app) were inspected at 390, 768 and 1440px. Each returned HTTP 200 and matched the local baseline's orange sidebar and page structure. The first restricted browser attempt was denied network access; a subsequent authorized read-only capture succeeded. See [deployed measurements](ui-ux/deployed-metrics.json) and the comparison images below. No deployment changes were made.

P0 means a critical broken workflow; P1 means a high-priority usability/accessibility concern; P2 means a refinement or maintenance issue. A small font is a readability concern, not by itself proof of a WCAG failure.

During implementation, axe caught a new palette pairing failure: `#C2410C` on `#FFE7D5` produced approximately 4.35:1. This was introduced during the redesign, then corrected with the darker `--color-text-accent`; it is not presented as a baseline failure. The completed accessibility checks pass.

Present UI states were reviewed: default and collapsed desktop navigation; mobile drawer, focus loop, Escape, navigation and desktop resize; untouched and filtered/search-empty listings; all five expanded recruitment teams, deep links, history and keyboard disclosure; FAQ; contact channels; and HTTP 404 recovery. The app uses synchronous local content, with no submission form, user authentication UI, tables, pagination controls, toast system or separate modal workflow to redesign. The root error boundary was inspected in source; an artificial runtime exception was not injected into the delivered app.

White primary-action text is used on the strong orange, never on the bright brand orange. Dark accent text is used on peach selected surfaces. Neutral borders and inactive icons prevent the interface from becoming uniformly orange. The original logo and student SVG illustration are preserved; the illustration's surrounding surface is softened.

Typography retains system Segoe UI / Arial with no font downloads. Shared text tokens are 0.75rem captions, 0.875rem supporting text/actions and 1rem body. Page headings use responsive ranges around 28–42px; the home/recruitment hero can reach 48–50px. Existing section hierarchy is preserved, with body line heights around 1.65–1.9. Main headings remain navy; orange is reserved for emphasis.

Spacing uses a 4px base with 4/8/12/16/20/24/32/40/48px tokens, alongside retained responsive page gutters. Shared radii are 8px controls, 12px cards and 16px sections. Cards use `0 2px 8px #252B3505`; hover emphasis uses `0 6px 18px #252B350D`. Controls use 44px minimum heights where applicable, with wrapping text allowed to increase their height.

Desktop keeps the existing 238px navigation width, its narrow/wide breakpoints, and useful 84px collapsed rail. Below 951px, navigation uses the native modal drawer. Short color/shadow transitions use a 160ms token; existing disclosure and drawer transitions remain small. Reduced-motion rules disable transitions/animation and smooth scrolling. Forced-colors selection uses an explicit system-color outline.

The final local initial-load layout-shift samples were zero across the 35 audited route/width combinations. This short local observation is not field Core Web Vitals data or a throttled performance benchmark. No font downloads, new animation libraries or runtime dependencies were added. The generated shared CSS grew from about 8.30kB to 8.72kB gzip; the entry-client chunk stayed unchanged at about 68.41kB gzip. Existing React Router future-version advisories remain non-blocking.

The first redesign iteration's contrast checks failed and were fixed before the passing final suite. Two newly authored test selectors initially contained an encoding error; they were corrected. The subsequent drawer-state assertion exposed the real existing behavior described above, which was fixed and retested. No test failures remain. After the passing 27-test suite, the only runtime follow-up was the favicon declaration; the affected asset, build, console and SEO checks were rerun.

## F. Deliberately deferred work

- Official announcements, scholarships, event schedules, recruitment dates/application destinations, telephone and map configuration still need approved content. Adding or inventing them would change product requirements and data handling, so the existing honest pending states remain.
- The Học tập team's duplicated requirements/benefits need editorial confirmation. The existing note and all 72 supplied recruitment bullets are preserved; the generated-output hash tests pass.
- Safari, Firefox, physical-device and screen-reader testing remain to be performed before a formal accessibility sign-off. Verification here used installed Chrome on Windows, keyboard operation and axe.
- Real-network performance profiling and field measurements should follow publication with production traffic. Local CLS and bundle observations do not substitute for those measurements.
- New submission forms, backend integration, pagination, loading skeletons, toast notifications and additional button variants are deferred until their actual workflows exist. The current synchronous local content does not need simulated loading or success states.
- Public deployment and GitHub push are excluded by the task. Review the local changes and screenshots before any separately authorized release.
